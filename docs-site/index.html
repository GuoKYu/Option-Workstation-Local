文档版本：v1.0 ｜ 编制日期：2026-08-24 ｜ 编制：产品/工程负责人 配套文档包：docs/ 全套；运行文档：操作手册.md

1. 项目背景

OptionWorkstation 是一个本地部署的美股期权分析工作站，面向期权研究者、量化爱好者与交易前分析场景，提供期权链、波动率曲面建模、多腿策略损益分析与研究审计台账能力。项目首期以"本地单机、数据自管、免云端依赖"为原则交付，规避云端部署的账号/白名单复杂度。

当前版本 0.1.0（Apache-2.0）已具备可运行形态：后端 Rust（axum）编译产物 option-workstation.exe 于 2026-08-24 在本机编译成功，前端 UI 可正常渲染，长桥 OAuth 本地模式连通。

2. 总体描述

2.1 产品前景

单机运行，浏览器访问 http://127.0.0.1:7311。用户通过 Longbridge OAuth 登录后，可切 replay/live 模式，进行期权研究与策略分析。

2.2 用户特征

具备期权基础知识的个人研究者/量化爱好者，单机使用，无多用户协作需求。

2.3 运行环境约束

  • 操作系统：Windows 10/11（64 位）。
  • 运行时：已编译 option-workstation.exe（约 20MB）+ 静态前端 frontend/dist。
  • 网络：Longbridge OpenAPI（CN 节点 openapi.longbridge.cn）；OAuth 回调 http://localhost:60355/callback（本地模式，无需长桥白名单）。
  • 依赖权限：LV1 实时行情(OpenAPI) + OPRA 美股期权行情(OpenAPI)。

2.4 假设与依赖

  • A1：用户持有有效 Longbridge OpenAPI 账号并开通相应行情权限。
  • A2：本机已安装 MinGW GNU 工具链与 Rust（GNU），详见 操作手册.md 第 3 节。
  • A3：编译期可访问 crates.io（受限网络下可用手机热点）。

3. 功能需求

3.1 行情接入与鉴权

  • FR-01 长桥 OAuth 登录：用户通过 OAuth 2.0 登录，本地模式回调 localhost:60355，无需配置白名单。/api/oauth/start、/api/oauth/callback、/api/oauth/status。
  • FR-02 连接状态管理：展示账号、行情协议、Trade API 状态、权限包；支持"更换并验证凭证"刷新 token。/api/connection、/api/debug/connectivity。
  • FR-03 正股行情：订阅正股 SubFlags::QUOTE，实时推送报价。
  • FR-04 期权行情：订阅期权 SubFlags::DEPTH（期权链/深度）；依赖 OPRA(OpenAPI) 权限，缺失时订阅通过但不推数据（见 R1）。

3.2 期权链与希腊字母

  • FR-05 期权链查询：按标的+到期列出合约与行权价、买卖盘、IV、希腊字母。/api/chain。
  • FR-06 希腊字母计算：对每行合约计算 IV（求解或取 SDK IV，约束 1%~400%）、及 Greeks。analytics.rs。
  • FR-07 合约表格渲染：前端 ChainTable.jsx 展示链；支持按到期/行权价筛选。

3.3 波动率曲面

  • FR-08 波动率上下文：返回微笑/曲面上下文数据。/api/volatility-context、/api/live/volatility-context。
  • FR-09 2D 热力图：以 Moneyness × DTE 渲染 IV 热力图（echarts heatmap）。SurfaceChart.jsx。
  • FR-10 3D 曲面：以 WebGL（echarts-gl surface）渲染 IV 三维曲面；无 WebGL 时降级为 2D。
  • FR-11 SVI/SVF 拟合：对微笑进行 SVI 拟合并叠加曲线。volatility.rs、strategy.rs/前端 SVI 曲线。

3.4 历史回放

  • FR-12 replay 模式：选择交易日/标的，按分钟回放快照，驱动曲面与策略分析。/api/replay/snapshot、/api/v1/replay/snapshot。
  • FR-13 回放控制：播放/暂停/拖拽时间轴（前端状态机）。

3.5 实时模式

  • FR-14 live 会话：建立实时会话、订阅、快照与 WebSocket 流。/api/live/session、/api/live/snapshot、/api/live/stream。
  • FR-15 实时限频保护：期权请求 65s 全局冷却（live.rs:47），触发时前端排队提示并自动重试（无害）。

3.6 多腿策略工作台

  • FR-16 策略 legs 编辑：增删腿、设置数量/方向。StrategyWorkbench.jsx、strategy_quantity 等状态。
  • FR-17 策略分析：调用 /api/strategy/analyze 返回损益、聚合 Greeks、盈亏平衡点等。

3.7 审计与研究台账

  • FR-18 审计记录：append-only 本地台账记录研究动作；支持查询与追加。/api/audit/records（GET/POST）、/api/audit/records/{id}。AuditPanel.jsx、audit.rs。

3.8 交易（预留）

4. 关键数据流

4.1 OAuth 登录（本地模式）

/api/oauth/start → 浏览器跳转长桥授权 → 回调 http://localhost:60355/callback → /api/oauth/callback 换 token → 本地保存 → /api/oauth/status 反映状态。

4.2 实时快照

/api/live/session（建会话/订阅）→ 后台 live.rs 拉行情写入 cache.depth → /api/live/snapshot 出快照 → /api/live/stream（WebSocket）持续推送 → 前端节流（2s）更新曲面。

4.3 历史回放

前端选交易日/标的 → /api/v1/replay/snapshot?... → replay.rs 读 Parquet → 返回曲面/波动率上下文 → AbortController 取消过期请求。

4.4 策略分析

前端 StrategyWorkbench 组装 legs → POST /api/strategy/analyze → strategy.rs 计算 → 返回损益/聚合 Greeks。

5. 关键设计决策

  • 本地模式免白名单：OAuth 回调用 localhost:60355，区别于云端 OW_OAUTH_REDIRECT_BASE（cloud 分支）。
  • 期权请求 65s 全局冷却：live.rs:47，避免触发长桥 301607 限频；单全局时间戳（非按标的分），见风险 R3。
  • OPRA 权限分离：正股（QUOTE）与期权（DEPTH/OPRA OpenAPI）是两套独立权限，缺期权权限时订阅通过但不推数据。
  • 前端节流与取消：曲面更新 2s 节流（surfaceUpdateRef）、回放请求 AbortController，避免抖动。
  • 编译工具链 GNU：因受限网络屏蔽微软域名，采用 MinGW-w64 GCC + stable-x86_64-pc-windows-gnu，规避 MSVC link.exe 缺失。

6. 部署拓扑

  • 单机：127.0.0.1:7311（Web）+ localhost:60355（OAuth 回调）。
  • 启动：start.bat（直接跑 exe）/ build-local.bat（编译+启动）。
  • 代码：main（本地主枝）/ cloud（云端分支）。

7. 质量属性

  • 可观测：RUST_LOG 分级日志（option_workstation / tower_http）。
  • 容错：限频/无报价提示不阻断行情流；订阅失败回滚（rollback_option_switch）。
  • 可移植：零白名单本地模式 + 独立云端配置。

0. 先理解判定逻辑（代码真因）

live.rs 判断是否"交易可用"靠两个长桥 OpenAPI 调用，任一成功即视为可用：

// live.rs:752-822（节选）
let trade_overview = trade.us_asset_overview().await.ok();        // 资产概览
let trade_balances  = if trade_overview.is_none() {
    trade.account_balance(Some("USD")).await.ok()                 // 账户余额（兜底）
} else { None };
let trade_connected = trade_overview.is_some() || trade_balances.is_some();
// ...
trade: trade_connected.then_some(trade),   // 为 false 时 TradeContext 不入库
  • 前端显示 Unavailable = trade_connected == false = us_asset_overview() 与 account_balance() 两个调用都返回 None（.ok() 把 Err/空都吞成 None）。
  • 一旦 false，TradeContext 不存入 engine → 所有 /api/trade/* 报 trade permission is unavailable for this token。

注意：这是长桥账户/授权层面的问题，OptionWorkstation 无需改代码。即便打通，本版 order_execution_enabled 还要求 paper_account && paper_execution_requested——即只支持模拟账户(paper)的模拟单，实盘下单锁定。

1. 项目概述

OptionWorkstation 是一个本地部署的美股期权分析工作站，用于期权链构建、隐含波动率曲面、希腊字母与套利/风险分析。

7. 常见问题排查

7.1 提示「已排队等待 Longbridge 限频窗口；当前 XXX 行情继续推送，约 59 秒后自动重试」

  • 出处：前端 frontend/src/App.jsx:379。
  • 根因：后端 rust-backend/src/live.rs:47 定义全局期权请求冷却 OPTION_REQUEST_COOLDOWN = 65 秒（live.rs:214-218）。该冷却是单个全局时间戳，所有期权类请求（切到期月订阅 + 后台 90 秒元数据刷新）共享。65 秒内再次请求期权链会被限频排队，到点自动重试。
  • 影响：无害。行情流不受影响，到点自动恢复。
  • 规避：避免在 65 秒内重复点 Start / 频繁切换到期月份；或等它自动重试。
  • （可选代码改进）：把 option_request_at 改为 HashMap<symbol, Instant>（按标的分冷却）、或让后台刷新与手动切换用独立时间戳。当前未改，不影响使用。

7.2 提示「selected expiration has no usable quotes yet」

  • 出处：后端 rust-backend/src/live.rs:1319 → 实际由 analytics.rs:648 的 anyhow::ensure!(!rows.is_empty(), "no usable option quotes") 触发。
  • 含义：选中到期日下的所有合约都构建不出一行有效期权数据（行要成立需算出一个落在 1%~400% 的有效 IV）。
  • 最常见根因（本项目实测）：缺「OPRA 美股期权行情 (OpenAPI)」权限。订阅被长桥接受但不推数据 → cache.depth 全空 → 无有效 IV → 报此错。
  • 验证：见 6.3 的 CLI 命令，返回 code=301604 即确认。
  • 次因（瞬态）：刚切到期月、期权深度行情还没推过来，几秒后自愈。
  • 连锁关系：常与 7.1 同时出现——65s 冷却挡在真正订阅行情之前，导致新到期月没订阅到数据，于是紧接着报「无可用报价」。
  • 处理：
  • 先确认已开通 OPRA(OpenAPI) 权限（见第 6 节），这是根治手段；
  • 若权限已就绪仍偶发，等几秒让其自动重试；
  • 个别到期月流动性极差（非主链）可换近月或标准月度到期。

7.3 编译报错（SSL / 网络 / 工具链）

现象 处理
link.exe not found 未用 GNU 工具链。确认 rustup default stable-x86_64-pc-windows-gnu，且 C:\mingw64\bin 在 PATH。
SSL / unable to get local issuer certificate build-local.bat 已设 CARGO_HTTP_SSL_NO_REVOKE=true。仍报错则确认网络能达 crates.io（必要时手机热点）。
crates.io 下载超时（直连被挡） 切手机热点；或检查 rust-backend/.cargo/config.toml 应为空（零自定义源），靠默认 crates.io + 环境变量。
gcc 找到但 rustup 不在 PATH build-local.bat 已显式加 C:\Users\SJTUH\.cargo\bin，重开 cmd 后重试。
sparse url must end with '/' / ssl-no-revoke 键不被识别 删除 config.toml 里的自定义 source 与 ssl-no-revoke 键，仅依赖环境变量。

7.4 启动后打不开 127.0.0.1:7311

  1. 确认 start.bat / build-local.bat 的 cmd 窗口仍开着（关窗即停服务）。
  2. 确认 target/release/option-workstation.exe 已生成（未编译成功则没有）。
  3. 检查防火墙是否拦了 7311 端口（本机回环一般不需放行）。
  4. 看 cmd 窗口日志是否有 panic / 长桥连接错误。
